# ChatBI 学习笔记：用大模型把中文问题变成 SQL 查询

> 这是我学习 Text-to-SQL / ChatBI 方向时边学边搭的一个小 Demo。
> 不是成熟产品，就是把"自然语言问数据"这件事从 0 跑通了一遍，
> 顺便记录每一步学了什么、踩了什么坑。

---

## 这个项目在学什么

ChatBI（Chat Business Intelligence）就是：业务人员不用写 SQL，用大白话问问题，
大模型自动翻译成 SQL 去查数据库，再把结果用人话讲回来。

常见产品：观远数据、帆软 FineBI、Power BI Copilot，核心逻辑都是这个。

我想搞懂的问题：
- 大模型怎么知道有哪些表、字段是什么意思？
- 怎么保证它生成的 SQL 不会瞎写、口径不会错？
- 从用户提问到拿到答案，中间数据流是怎么走的？

---

## 整体流程

```
用户问："广州哪家店营收最高？"
        │
        ▼
┌─────────────────┐
│  DeepSeek 大模型  │  ← 我把表结构和指标口径写在 metrics.yaml 里喂给它
│  把中文翻译成 SQL │
└─────────────────┘
        │
        ▼
┌─────────────────┐
│   SQLite 数据库   │  ← 20 家门店 6 个月的销售数据
└─────────────────┘
        │
        ▼
┌─────────────────┐
│  大模型总结结果   │  ← "广州天河城店营收最高，约 XX 万"
└─────────────────┘
```

## 技术栈

- **后端**：Python + FastAPI
- **大模型**：DeepSeek API（兼容 OpenAI 接口格式）
- **数据库**：SQLite（零依赖，换连接串就能接 MySQL）
- **前端**：一个简单的 HTML 聊天页面
- **语义层**：metrics.yaml 写指标口径

## 每个文件我学了什么

| 文件 | 我在里面学了什么 |
|---|---|
| `data/generate_data.py` | 星型模型怎么设计：事实表（销售记录）+ 维度表（门店信息）；为什么要建索引 |
| `metrics.yaml` | **指标口径怎么写**：比如"客单价 = 营收 ÷ 订单数"，业务黑话怎么翻译成 SQL 逻辑 |
| `app/llm.py` | Prompt 工程：怎么把表结构和指标口径喂给大模型，让它生成正确的 SQL |
| `app/main.py` | FastAPI 接口怎么写；怎么限制只允许 SELECT（防止危险 SQL）；一次请求的完整链路 |
| `static/index.html` | 前后端怎么用 JSON 通信，怎么调接口 |

## 我踩过的坑（真实记录）

1. **一开始大模型瞎写字段名**
   → 原因：Prompt 里没给它表结构，它自己脑补。
   → 解决：把表结构和字段说明写在 metrics.yaml 里，每次请求都拼进 Prompt。

2. **指标口径不一致**
   → 大模型自己算"客单价"时乱算，有时候用营收除以订单数，有时候用营收除以用户数。
   → 解决：在 metrics.yaml 里写死每个指标的计算公式，Prompt 里强调"必须按这个口径算"。

3. **安全问题**
   → 大模型可能生成 DROP/DELETE 这种危险 SQL。
   → 解决：后端加了限制，只允许 SELECT 开头的语句执行。

## 怎么跑起来

```bash
# 1. 装依赖
pip install -r requirements.txt

# 2. 配 DeepSeek API Key
#    去 platform.deepseek.com 申请，然后设环境变量
set DEEPSEEK_API_KEY=sk-你的key

# 3. 生成数据库（已经有 retail.db 可以跳过）
python data/generate_data.py

# 4. 启动
python -m uvicorn app.main:app --reload --port 8000

# 5. 浏览器打开
http://localhost:8000
```

## 学习这个项目我搞懂了什么

- ChatBI 的核心不是大模型多聪明，而是**指标语义层写得好不好**——口径写清楚了，AI 才不会瞎答
- Text-to-SQL 的关键是 Prompt 工程，把表结构和业务规则喂全
- 大模型输出不能直接信，后端要加安全限制和校验
